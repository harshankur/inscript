Technical Architecture

Designed to be lightweight, portable, and developer-friendly.

Two Modes, One System

CMS Mode (npm run dev) runs locally with the full rich text editor, draft system, and write capabilities. This is where you create and edit content.

Published Mode (npm run publish) generates a static, readonly version of your blog. This is what you deploy to the web for readers. Server-free.

Static API (data.json)

Inscript parses your markdown and generates a unified data.json. The built-in Readonly App consumes this to render your blog with pixel-perfect fidelity to the editor. Alternatively, your own frontend (Astro, Next.js, etc.) can consume this data.

Quick Start

Get up and running in minutes.

1. Add Submodule

Run this from your project root:

git submodule add https://github.com/harshankur/inscript.git inscript

2. Install & Setup

Run the interactive wizard to configure your blog identity and security:

cd inscript && npm install && npm run setup

💡 Tip: Forgot your credentials? Delete the AUTH_USERNAME and AUTH_PASSWORD_HASH lines from your .env and run npm run setup to create new ones.

3. Run CMS

Standard Run:

npm run dev

Or via Docker Compose:

docker-compose up --build

4. Enable Git Integration

To commit and push directly from the UI, set this in your .env:

ALLOW_PUSH=true

Docker Note: Uncomment the .gitconfig and .ssh volumes in docker-compose.yml to share your host credentials.

Configuration & Environment

Customize Inscript to fit your specific workflow.

Variable Status Description
TITLE Required The display title of your CMS and Blog.
SITE_URL Required Public URL (used for Sitemap and Robots selection).
CONTENT_DIR Required Path to your markdown content (relative to inscript/).
STATIC_DIR Required Path to your images/assets (relative to inscript/).
DRAFTS_DIR Required Path for storing drafts and editing history.
DIST_DIR Optional Override the build output location (default: ../dist).
FAVICON Optional Custom favicon path (relative to STATIC_DIR).
SERVER_PORT Optional Local API server port (default: 2221).
CLIENT_PORT Optional React dev server port (default: 2222).
ALLOWED_HOSTS Optional Allowed hosts for backend access.
AUTH_ENABLED Optional Enable local password protection (default: true).
AUTH_USERNAME Optional Admin username for login.
AUTH_PASSWORD_HASH Optional BCrypt hash of your admin password.
SESSION_SECRET Optional Random string for signing session cookies.
ALLOW_PUSH Optional Enable Git Push directly from the UI.

Build Commands

Two modes for writing and publishing.

npm run dev

Runs the CMS locally with full editing capabilities. Use this on your computer or in-house server for writing and managing content. Not for public deployment.

npm run publish

Builds the readonly static blog with data.json and sitemap.xml. This is what you deploy to Netlify, Vercel, or any hosting platform for public viewing.

Deploying Your Blog

Deploy the readonly published version to any static hosting platform.

Netlify

Add this to your root netlify.toml to build and deploy your published blog: 

[build]
  command = "cd inscript && npm install && npm run publish"
  publish = "dist"

Self Hosting

Simply serve the contents of your DIST_DIR (default ../dist) using Nginx, Apache, or any static server. No Node.js runtime is required in production!
